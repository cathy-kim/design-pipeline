# Question Bank — 요구사항 구체화 질문

design-brief Phase 2 가 쓰는 질문 목록. 원칙은 "이미 아는 것은 묻지 않고, 모르는 것만 선택지와 함께 묻는다".

## 1. 질문 원칙

1. **라운드당 최대 3문항, 최대 3라운드.** 3라운드가 끝나면 남은 공백은 가정으로 채우고 brief 의 `가정` 표에 적는다.
2. **선택지를 준다.** 열린 질문은 라운드당 1개까지. 나머지는 2~4개 선택지 + "기타".
3. **컨텍스트 우선.** 요청문·참조 URL/이미지·기존 `.design/brand_config.json`·리포 코드에서 추론 가능한 것은 묻지 않고 가정으로 기록한다.
4. **사용자 언어로.** "컴포넌트 구조", "토큰" 같은 구현 용어로 묻지 않는다.
5. **금지:** 한 번에 5문항 이상, 이미 답한 것 재질문, 비밀값·개인정보 요구.

## 2. 필드 우선순위 (무엇을 먼저 묻나)

| 우선 | 필드 | 왜 | 비어 있으면 |
|---|---|---|---|
| P1 | `purpose` 화면/서비스의 핵심 목적, 전환 목표 | 화면 목록과 우선순위가 여기서 나온다 | 반드시 질문 |
| P1 | `content` 반드시 들어갈 요소 | 화면 목록의 근거 | 반드시 질문 |
| P1 | `platform` web / mobile-rn / print / SNS 캔버스 | system·ui 출력 형식이 갈린다 | 요청문에서 추론, 불가하면 질문 |
| P2 | `audience` 주 사용자 | 톤·밀도·타이포 크기 | 질문(선택지) |
| P2 | `tone` 원하는 분위기 | 팔레트 3축의 Mood | 질문(선택지) |
| P3 | `brand` 기존 브랜드 자산 유무 | 팔레트 결정 분기 | `.design/brand_config.json` 존재로 판정, 없을 때만 질문 |
| P3 | `reference` 참고 URL/이미지 | Inspired/Recreation 분기 | 질문(선택), 있으면 라우터에 design-tokens 를 권한다 |
| P3 | `constraints` 기한·기술 스택·접근성 수준·다국어 | 범위 결정 | 기본값 가정(WCAG AA, 한국어 우선) |

## 3. 라운드 구성

| 라운드 | 묻는 것 | 끝나는 조건 |
|---|---|---|
| R1 | P1 공백 전부 (최대 3) | purpose·content·platform 확정 |
| R2 | P2 + 화면 목록 확인 ("이 화면들로 충분한가요? 빠진 것/뺄 것") | 화면 목록과 P0 화면 합의 |
| R3 | 브랜드 없음이면 팔레트 3축(Sector·Positioning·Mood/Philosophy) 확인. 브랜드 있으면 남은 제약 | 팔레트 입력 또는 제약 확정 |

요청이 충분히 구체적이면 R1 을 건너뛰고 바로 요약 확인(§6 "충분" 패턴)으로 간다.

## 4. AskUserQuestion 매핑

AskUserQuestion 이 있으면 한 라운드 = 한 호출, 문항당 2~4 선택지. 예:

```json
{
  "questions": [
    {
      "question": "이 화면에서 사용자가 가장 먼저 해야 하는 행동은?",
      "header": "핵심 목적",
      "multiSelect": false,
      "options": [
        { "label": "가입/구매 전환", "description": "CTA 중심, 랜딩형" },
        { "label": "정보 확인", "description": "읽기 중심, 목록/상세형" },
        { "label": "데이터 입력", "description": "폼 중심" },
        { "label": "현황 모니터링", "description": "대시보드형" }
      ]
    }
  ]
}
```

없으면 번호 목록 산문으로 같은 문항을 낸다:

```
디자인 브리프를 위해 확인할게요 (1/3 라운드):

1. 이 화면에서 사용자가 가장 먼저 해야 하는 행동은?
   (a) 가입/구매 전환 (b) 정보 확인 (c) 데이터 입력 (d) 현황 모니터링 (e) 기타
2. ...
```

## 5. 디자인 유형별 핵심 질문

### Landing Page
1. 주요 전환 목표는? (회원가입 / 문의 / 구매 / 다운로드)
2. 필요한 섹션은? (Hero, Features, Social proof, Pricing, FAQ, CTA)
- 선택: 참고 랜딩페이지, 꼭 강조할 메시지

### Dashboard
1. 표시할 핵심 지표(KPI)는? (매출, 사용자 수, 전환율 …)
2. 표현 방식은? (숫자 카드 / 차트 / 테이블)
- 선택: 필터·검색 필요 여부, 실시간 갱신 여부

### Form (로그인·가입·설문)
1. 필요한 입력 필드는? (이메일, 비밀번호, 이름, 전화번호 …)
2. 소셜 로그인·비밀번호 찾기 등 부가 기능은?

### List / Table
1. 어떤 데이터를 보여주나? (사용자, 주문, 제품 …)
2. 각 항목에 필요한 정보는? (이름, 상태, 날짜, 액션)

### Detail / Profile
1. 이 화면에서 사용자가 내려야 할 결정은? (구매, 연락, 저장)
2. 필수 정보 블록은? (요약, 사양, 리뷰, 관련 항목)

### SNS 카드 (캐러셀)
1. 몇 장인가? 각 장의 역할은? (커버 1 + 본문 N + 마무리 1)
2. 핵심 메시지와 출처는?
- 캔버스는 기본 1080×1350(4:5). 다르면 질문.

## 6. 누락 필드별 질문 문구

| 누락 | 문구 |
|---|---|
| context | "어떤 서비스/앱의 화면인가요? 예: 헬스케어 앱, B2B SaaS, 쇼핑몰" |
| purpose | "이 화면에서 사용자가 주로 무엇을 하길 원하시나요? 예: 정보 확인, 입력, 구매" |
| tone | "원하는 분위기가 있나요? (a) 미니멀·깔끔 (b) 활기·다채 (c) 전문·신뢰 (d) 따뜻·친근" |
| content | "이 화면에 꼭 들어가야 할 요소가 있나요? 예: 로고, 특정 버튼, 이미지, 문구" |
| audience | "주 사용자는? (a) 일반 소비자 (b) 실무자/전문가 (c) 관리자 (d) 기타" |

## 7. 팔레트 3축 질문 (브랜드 없음 분기, R3)

축 정의와 값은 [sector-mapping.md](sector-mapping.md), [mood-philosophy-mapping.md](mood-philosophy-mapping.md).

1. **Sector** — "가장 가까운 업종은? (a) Tech/SaaS (b) Beauty (c) Finance (d) Food (e) Fashion (f) Wellness (g) Eco (h) Real Estate (i) Education (j) Hospitality" — 요청문에서 추론되면 묻지 않는다.
2. **Positioning** — "가격·격의 위치는? (a) Luxury (b) Premium (c) Standard (d) Mass"
3. **Mood × Philosophy** — "지금 원하는 분위기(Mood)와 오래 지킬 성격(Philosophy)은?" Mood 12개 중 2~4개를 tone 답에서 골라 선택지로 낸다.

## 8. 응답 처리

**충분**
```
정리할게요:
- 플랫폼: [platform] / 목적: [purpose]
- P0 화면: [screen list]
- 톤: [tone]
이대로 brief 를 작성합니다.
```

**한 가지 남음**
```
거의 다 됐어요. 마지막으로 하나만: [질문]
```

**불충분하지만 3라운드 소진**
```
남은 항목은 아래 가정으로 진행합니다. brief.md 의 '가정' 표에 기록해 두었고, 언제든 바꿀 수 있어요.
- [필드]: [가정값] (근거: [추론 근거])
```

## 9. 예시

**요청:** "로그인 화면 만들어줘"
→ R1: (1) 어떤 서비스의 로그인? (2) 소셜 로그인 필요? 선택지 Google/Apple/Kakao/없음

**요청:** "헬스케어 앱 로그인, 이메일/비밀번호 + Google 로그인, 미니멀 화이트 테마"
→ 질문 없음. "충분" 패턴으로 요약 확인 후 brief 작성. 브랜드 없음이면 R3 팔레트 3축만 확인(Sector=Wellness Clinical 추론, Positioning 만 질문).
